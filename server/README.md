# سرور ورود با کد پیامکی (Reralo) — اتصال به ملی‌پیامک

## ۱) آماده‌سازی در پنل ملی‌پیامک
1. از بخش «پیامک پترن (خدماتی)» یک الگو بسازید، مثلا: `کد ورود شما به Reralo: {0}` (فقط یک متغیر برای کد؛ شکل نوشتن متغیر را طبق راهنمای خود پنل بنویسید).
2. صبر کنید الگو توسط مدیر سامانه تأیید شود. بعد از تأیید، «کد متن پیش‌فرض» (bodyId) را یادداشت کنید.
3. نام کاربری و رمز عبور (یا ApiKey) پنل را داشته باشید. طبق مستندات ملی‌پیامک، پنل ممکن است استفاده از ApiKey به‌جای رمز و ثبت IP مجاز را الزامی کند. اگر چنین بود، IP سرور خودتان را در پنل ثبت کنید.
4. اعتبار پنل شارژ باشد و مدارک حساب تکمیل شده باشد (در غیر این صورت ارسال خطا می‌دهد).

## ۲) اجرای سرور
Node.js نسخه‌ی ۱۸ یا بالاتر، روی سرور با HTTPS. متغیرهای محیطی (فقط روی سرور، نه داخل سایت):

| متغیر | توضیح |
|---|---|
| `SMS_PROVIDER` | `melipayamak` (پیش‌فرض) |
| `MELI_USERNAME` | نام کاربری پنل |
| `MELI_PASSWORD` | رمز عبور یا ApiKey پنل |
| `MELI_BODY_ID` | کد متن پیش‌فرض الگوی تأیید‌شده |
| `SESSION_SECRET` | رشته‌ی تصادفی بلند (حداقل ۲۴ نویسه) |
| `ALLOWED_ORIGIN` | آدرس دقیق سایت، مثلا `https://reralo.ir` |
| `PORT` | پورت (پیش‌فرض ۳۰۰۰) |

اجرا: `node otp-server.js`

سپس در `site/index.html` مقدار `const AUTH={url:""}` را به آدرس همین سرور تغییر دهید، مثلا `const AUTH={url:"https://api.reralo.ir"}`، و سایت را روی دامنه‌ی خودتان بگذارید.

## ۳) تست
- بدون پیامک واقعی: `SMS_DRY_RUN=1` بگذارید؛ کد در لاگ سرور چاپ می‌شود.
- تست واقعی: با شماره‌ی خودتان ورود را امتحان کنید. اگر `sms_failed` گرفتید، لاگ سرور کد خطای ملی‌پیامک را نشان می‌دهد (مثلا ۰ = نام کاربری/رمز اشتباه، ۲ = اعتبار کم، ‎-4 = bodyId نادرست یا تأییدنشده، ‎-5 = متغیرهای الگو نخواندند، ۳۵ = شماره در لیست سیاه مخابرات).

## نکات امنیتی
- نام کاربری، رمز و ApiKey را هرگز داخل `index.html`، گفتگو یا گیت نگذارید. اگر لو رفت، از پنل عوضش کنید.
- محدودیت‌های سرور: هر شماره ۱ پیامک در دقیقه و ۵ در ساعت، هر IP حداکثر ۲۰ در ساعت، کد ۲ دقیقه اعتبار دارد و ۵ بار اشتباه مجاز است.
- کدها در حافظه نگه داشته می‌شوند. برای چند سرور یا ری‌استارت پایدار، Redis یا دیتابیس بگذارید.
- ورود فعلی فقط وضعیت ورود را در مرورگر نشان می‌دهد؛ برای حساب واقعی، پروفایل و سفارش‌ها هم باید در دیتابیس سرور ذخیره شوند.
- برای کاوه‌نگار: `SMS_PROVIDER=kavenegar`، `SMS_API_KEY` و `SMS_TEMPLATE` را بگذارید.

## ورود با گوگل
1. در Google Cloud Console یک OAuth client ID از نوع Web application بسازید و آدرس سایت را در Authorized JavaScript origins بدهید.
2. مقدار Client ID را روی سرور در `GOOGLE_CLIENT_ID` و در `site/index.html` در `const GOOGLE_CLIENT_ID="";` بگذارید (Client Secret لازم نیست).
3. مسیر `POST /auth/google` توکن گوگل را روی سرور بررسی می‌کند (امضا، مخاطب، صادرکننده، انقضا، تأییدشده بودن ایمیل). روی پیش‌نمایش claude.ai کار نمی‌کند.
